# 架构草案

```text
React/TypeScript 界面
        │ Wails 绑定
        ▼
应用服务：任务、取消、进度、历史
        ├── Go 探测引擎：输入 → DNS → TCP → TLS → HTTP → 本机环境
        ├── 规则引擎：证据 ID → 可能原因
        ├── 分享管线：脱敏 → JSON / HTML / Issue Markdown
        └── 本地 JSON 历史
```

阶段 1 的探测引擎和 CLI 不依赖 Wails 或 React，可单独测试。每层输出结构化证据，包括 ID、状态、耗时、值和错误类别；未执行步骤也有状态和原因。规则读取证据，输出推断及依据 ID，不覆盖事实字段。

当前引擎按 DNS、TCP、TLS、HTTP 顺序直连探测。TLS 诊断连接先获取对端证书，再用系统或指定的根证书执行独立验证；验证失败时保留证书证据并跳过 HTTP。HTTP 只读取响应头，记录逐跳状态与耗时，限制跳转次数。每层有独立超时，另有总超时与取消信号。

Windows 代理信息来自当前用户的 Internet Settings 注册表，网卡信息来自 Go 网络接口 API。HTTP 当前不使用系统代理；这样各层直连结果可比较，但代理专用网络需要后续增加代理路径探测。

原始记录只存本机；分享时复制数据、先脱敏再渲染，且用户可预览。限制超时、重定向次数与 HTTP 读取量。凭据、URL 查询参数、代理信息、本机地址和路径均视为敏感内容。

规划目录：`cmd/` 放 CLI，`internal/` 放探测、规则、脱敏、报告与存储，`frontend/` 放桌面界面，`scripts/` 放开发脚本，`docs/` 放课程证据。阶段 0 只建立最小桌面入口。
