# 五分钟演示步骤

1. 打开 NetEvidence，输入 `https://dazidazi.com/`，运行单次诊断。说明 DNS、TCP、TLS、HTTP 和手动代理是不同证据层；当前是否成功以现场结果为准。
2. 切换“网址入口对比”，仍输入同一 URL。观察 HTTP/HTTPS 和 `www` 有无四种入口的响应、跳转与耗时。此模式不会请求原网址的路径或查询，也不写入历史。
3. 切换“连续采样”，选择 10 秒间隔、5 分钟时长。演示样本数、成功率和首次异常；可点击“取消检查”提前结束。只有异常样本与首个成功样本写入本机历史。
4. 在历史中打开一条样本，预览脱敏 JSON 或 Issue Markdown，说明具体 IP、代理地址和 URL 路径不会出现在分享报告中。
5. 在“对比诊断”中选择两条历史，展示分层状态、耗时及代理、网卡、DNS 答案变化标志。强调变化只是线索，不等于根因。
6. 打开“浏览器记录”，导入 `docs/samples/browser-failure.har`。主文档是 200，但脚本为 503、图片无 HTTP 响应、接口耗时 3.8 秒。选一条相近的本机诊断演示并排对照，并说明 HAR 不写入历史。

可重复运行 `scripts/verify-site.ps1 -Domain dazidazi.com`，得到四入口的 CLI 分层摘要。模拟端口拒绝时，选择一个未监听的 `127.0.0.1` 端口：DNS 显示字面量 IP 跳过，TCP 应显示拒绝，TLS 与 HTTP 跳过。不要把包含原始本机证据的历史 JSON 发给他人。
