# 需求与验收标准

## 场景

用户遇到网站或服务无法访问，支持人员无法复现。用户在 Windows 本机输入目标，运行诊断，把脱敏报告附到 GitHub Issue 或技术支持工单。工具不依赖自建后端。

## MVP

| 编号 | 能力 | 验收 |
| --- | --- | --- |
| F1 | 输入规范化 | 接受 URL、域名、`host:port`；展示规范化目标并拒绝含糊输入 |
| F2 | DNS | 记录耗时、IPv4/IPv6 和错误类别 |
| F3 | TCP | 记录连接耗时，分类超时、拒绝、不可达 |
| F4 | TLS | 记录握手耗时、版本、证书域名和有效期检查 |
| F5 | HTTP | 记录状态码、响应耗时和有限的重定向链 |
| F6 | 本机环境 | 读取系统代理和基础网络信息，不修改设置 |
| F7 | 规则 | 每条“可能原因”链接证据 ID，区分事实与推断 |
| F8 | 报告 | 导出 JSON、HTML、GitHub Issue Markdown |
| F9 | 隐私 | 分享前脱敏 Windows 用户名、本机目录、局域网 IP、MAC、Cookie、Authorization、URL Token，允许预览 |
| F10 | 历史 | 本地 JSON 保存诊断，可比较两次状态和耗时 |

探测须支持取消、逐层及总超时。一层失败仍保留已有证据，后续步骤标注跳过原因。结果包含时间、目标、选项、平台及工具版本。测试优先使用本地假服务器，避免依赖公网稳定性。

首版排除完整抓包、驱动、原始套接字、管理员权限、系统网络配置修改、自动修复、付费服务器、Docker、WSL、虚拟机，以及把 traceroute 作为必备能力。
