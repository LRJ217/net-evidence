# 阶段 2 验证记录

记录日期：2026-10-17（北京时间）。

## 原理与实现

`internal/share` 从原始诊断结果显式构造新的分享对象。只有逐字段审查过的值进入报告；原始结果保持不变。分享版保留各层状态、耗时、错误类别、HTTP 状态码、证书验证结论及证据 ID。URL 只保留目标主机、端口和路径／查询是否存在的标记；DNS 与网卡 IP、MAC、代理详情、证书名称和原始错误消息用标记代替。

规则根据结构化状态和错误类别生成固定文案，每条推断都列出证据 ID。HTML 使用自动转义模板。CLI 默认生成脱敏 JSON；`-format html` 和 `-format issue` 生成其他分享格式，`-format raw-json` 才输出本机原始证据。`-out` 使用只创建模式，避免覆盖已有报告。

## 验证证据

- `go test ./... -count=1`：隐私回归测试把 Windows 用户路径、URL Token、Cookie、Authorization、代理凭据、私网 IP、MAC 和网卡名称注入原始证据，检查三种分享格式均无泄漏，且原始结果未被修改。
- 规则测试覆盖 DNS 失败、TCP 拒绝、证书时间异常、HTTP 5xx 和未发现明确故障，并检查依据 ID。
- `go vet ./...` 与 Windows CLI 构建通过。
- `scripts/dev.ps1 -Task build`：前端 TypeScript 检查与构建、Go 测试与静态检查、CLI 和 Wails Windows 桌面构建均通过。
- CLI 对 `127.0.0.1:1` 的本机拒绝连接生成 JSON、HTML、Issue Markdown；三种输出均未包含输入 URL 中的测试令牌，分享目标显示为脱敏标记。
- CLI 对已有 `-out` 路径拒绝覆盖。

## 剩余风险

- 脱敏是保守的：所有 IP 和证书名称都会隐藏，可能减少远程排查细节。用户需要在本机查看 `raw-json` 才能获得完整信息。
- 目标域名仍保留在分享报告中，因为它是诊断对象；域名本身敏感时发送前应手动检查或不发送。
- 规则只能给出可能原因，不能证明故障根源。HTTP 直连结果与使用系统代理的浏览器可能不同。
