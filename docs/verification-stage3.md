# 阶段 3 验证记录

记录日期：2026-10-18（北京时间）。

## 原理与实现

Go 桌面服务以一次一个任务的方式运行诊断，通过 Wails 事件发送逐层结果与完成结果。取消信号进入探测引擎，已完成的部分仍能生成报告并保存。React 界面提供目标输入、超时选择、状态卡片、分层结构化详情、推断依据、报告预览与导出。

每次诊断将原始证据写入本机 JSON 历史。历史列表只提供脱敏摘要；报告预览、打开历史和对比都重新读取记录并输出脱敏内容。文件名 ID 严格校验，单条记录有大小上限，损坏文件跳过并计数。HTML 预览在空权限的沙箱 iframe 内渲染；导出只允许三种分享格式，使用只创建模式。

## 验证证据

- `go test ./... -count=1` 与 `go vet ./...` 通过；测试覆盖进度序列、取消后保留部分证据、忙碌任务拒绝、历史读写及坏文件、路径穿越拒绝、对比状态和耗时差值、历史摘要与预览脱敏。
- `npm run check`、`npm run build` 通过；`scripts/dev.ps1 -Task build` 完成前端、Go 测试及 Windows Wails 桌面构建。
- 在 Windows 桌面程序中对本机拒绝连接目标运行诊断，逐层结果、推断与历史记录正常显示；输入中的测试 Token 未出现在脱敏报告中。
- 桌面程序中切换 HTML 预览可看到渲染后的报告；运行第二次诊断后，历史出现两条记录，选择两条记录可生成分层对比表。
- 慢响应测试目标在原先 8 秒 HTTP 层超时后给出 timeout 结果；随后将桌面 HTTP 层超时调整为所选总超时，使取消操作有足够时间。取消的服务层自动化测试通过。更新后的实际界面取消操作尚未完成验证。

## 剩余风险

- 原始历史包含 URL 路径、查询及本机环境信息，只适合保存在受信任的当前用户目录；分享时应使用桌面导出的脱敏报告。
- 历史列表最多展示最近 100 条，但旧文件不会自动删除；磁盘占用会随诊断次数增加。
- 对比显示状态与耗时变化，只是观察结果，不证明根因。HTTP 当前直连目标，与使用系统代理的应用可能不同。
- 实际界面取消与导出文件对话框仍需在交付阶段进行手动回归。
