# 阶段 3 验证记录

记录日期：2026-10-18（北京时间）。

## 原理与实现

Go 桌面服务以一次一个任务的方式运行诊断，通过 Wails 事件发送逐层结果与完成结果。取消信号进入探测引擎，已完成的部分仍能生成报告并保存。React 界面提供目标输入、超时选择、状态卡片、分层结构化详情、推断依据、报告预览与导出。

每次诊断将原始证据写入本机 JSON 历史。历史列表只提供脱敏摘要；报告预览、打开历史和对比都重新读取记录并输出脱敏内容。文件名 ID 严格校验，单条记录有大小上限，损坏文件跳过并计数。HTML 预览在空权限的沙箱 iframe 内渲染；导出只允许三种分享格式。用户经系统保存对话框确认替换后，可覆盖已有报告。

## 验证证据

- `go test ./... -count=1` 与 `go vet ./...` 通过；测试覆盖进度序列、取消后保留部分证据、忙碌任务拒绝、历史读写及坏文件、路径穿越拒绝、对比状态和耗时差值、历史摘要与预览脱敏。
- `npm run check`、`npm run build` 通过；`scripts/dev.ps1 -Task build` 完成前端、Go 测试及 Windows Wails 桌面构建。
- 在 Windows 桌面程序中对本机拒绝连接目标运行诊断，逐层结果、推断与历史记录正常显示；输入中的测试 Token 未出现在脱敏报告中。
- 桌面程序中切换 HTML 预览可看到渲染后的报告；运行第二次诊断后，历史出现两条记录，选择两条记录可生成分层对比表。
- 慢响应测试目标在原先 8 秒 HTTP 层超时后给出 timeout 结果；随后将桌面 HTTP 层超时调整为所选总超时。实际界面点击取消后出现“诊断已取消”并保留 DNS、TCP 证据；取消结果现按“未完成”归类，规则不再把取消解释为网络故障。
- Windows 上当前用户配置了手动 HTTP 代理。对 `https://youtube.com` 的本机实测：直连 TCP 在 3 秒超时，经系统手动代理取得 HTTP 200；桌面界面同步显示两个路径和“代理可访问”的历史摘要。测试只记录状态和脱敏证据，未公开代理地址。
- 本地假代理覆盖手动代理地址解析、PAC 跳过、DNS 失败但代理成功、HTTPS CONNECT；分享报告测试检查代理地址、URL Token 和原始错误文本仍被隐藏。
- 实际桌面保存对话框将 JSON 脱敏报告导出到测试文件，文件中的目标地址、代理地址和原始错误文本均为脱敏标记。
- IPv4、IPv6 的首个解析地址现在分别并行尝试，原始历史保留两次尝试的地址、状态和耗时，分享报告只保留地址族及脱敏状态。单地址失败时仍可在本机卡片看到实际尝试的 IP；本机拒绝连接目标在新构建的桌面程序中验证了这一点。
- 历史侧栏已显示文件数和总占用，并提供逐条删除和手动按 30、90、180 天清理。单元测试覆盖清理只删除过期的有效记录、保留损坏文件、拒绝非法 ID；桌面界面确认显示了占用数字和清理控件。
- 针对用户提交的项目评审报告，补充了字面量 IP 跳过 DNS 的语义和连接重置分类；桌面报告预览可复制当前脱敏格式。系统保存对话框确认替换已有文件后，导出先写入同目录临时文件再替换目标；本地测试覆盖已有文件替换和临时文件清理。

## 剩余风险

- 原始历史包含 URL 路径、查询及本机环境信息，只适合保存在受信任的当前用户目录；分享时应使用桌面导出的脱敏报告。
- 历史列表最多展示最近 100 条；旧文件不会自动删除，需要用户通过界面手动清理。占用数字统计全部 JSON 文件，包括未展示或损坏的文件。
- 对比显示状态与耗时变化，只是观察结果，不证明根因。HTTP 当前直连目标，与使用系统代理的应用可能不同。
- 代理探测只复现手动系统代理地址，不运行 PAC、不读取浏览器扩展配置，也不执行 Windows 的代理绕过规则。它与浏览器真实请求路径仍可能不同。
