# NetEvidence 使用说明

## 安装与启动

在 Windows 11 上运行 `build/bin/NetEvidence-amd64-installer.exe`，或直接运行 `build/bin/NetEvidence.exe`。安装包使用当前用户安装范围，默认写入当前用户的应用目录；桌面程序依赖 Microsoft WebView2 Runtime。安装包目前未进行代码签名，属于本地开发构建，尚未公开发布。

## 单次诊断

输入完整 URL、域名或 `host:port`，选择总超时并点击“开始诊断”。DNS、TCP、TLS、HTTP 依次显示结果；桌面端另外尝试已配置的系统手动代理。若浏览器能访问而直连 TCP 超时，应分别查看直连与代理访问卡片。PAC 和浏览器扩展代理不会被完整复现。

“分层详情”与“可能原因”显示脱敏证据和推断。历史侧栏的原始记录只保存在本机；分享时使用报告预览、复制或另存为文件功能。分享前仍应检查内容。

## 连续采样

选择“连续采样”，设置单次超时、10/30/60 秒间隔以及 5/10/30 分钟时长。程序依次采样，不会重叠执行；到达时长、最大次数、关闭窗口或点击取消后停止。界面显示样本数、成功率、首次异常、每次结果及故障层。

连续采样只把异常样本和首个成功样本写入本机历史，避免每次成功都生成一份原始记录。当前窗口中的完整采样汇总不会跨程序重启保留；已保存的样本可在历史中打开并导出脱敏报告。“成功”要求直连与已配置的代理探测均正常；“直连可访问，代理异常”计为异常。成功率仅指本工具当次观测，不等于网站的整体可用率。

## 四种网址入口

选择“网址入口对比”，输入主域名或带 `www` 的主域名。程序并行检查 HTTP/HTTPS 与有无 `www` 的首页。输入中的路径和查询参数不会带入四个请求；非标准端口、IP 和其他子域名不适用。表格显示每个入口的分层状态、HTTP 状态码、脱敏后的最终地址与耗时。HTTP 入口的 TLS“跳过”表示未对初始入口单独探测 TLS，HTTP 请求仍可能跳转至 HTTPS。若显示“直连可访问，代理异常”，应查看直连 HTTP 成功与代理失败是两条不同的路径。入口对比只保留在当前窗口，不写入历史。

## 比较网络环境

“对比诊断”可选择两条本机记录。除了分层状态与耗时，还会提示手动代理、PAC、环境变量代理、网卡及其地址是否改变；两次目标相同时还会比较 DNS 解析结果。比较只输出变化标志，不输出代理地址、网卡名称或 IP。网卡变化可能与 VPN 切换有关，但不能单凭它证明 VPN 状态；DNS 答案变化也不能证明 DNS 配置被修改。

## 浏览器 HAR 分析

在浏览器开发者工具的“网络”面板开始录制，重现网页问题，然后导出经过敏感信息清理的 HAR 文件。回到 NetEvidence 的“浏览器记录”页点击“选择 HAR 文件”。工具支持最大 20 MiB、最多 20,000 条请求的文件；只读取 HTTP(S) 请求。可用 [模拟浏览器故障 HAR](samples/browser-failure.har)熟悉界面。

页面显示首个 HTML 文档是否得到正常响应、无 HTTP 响应、4xx/5xx、超过 3 秒的请求和涉及的主机。页面主机由首个 HTML 请求推定，缺少 HTML 时取首条 HTTP(S) 请求。异常表格只显示最多 200 条，按无响应、5xx、4xx、慢请求排序；URL 路径、查询、用户信息会隐藏。选择一条本机历史记录，可并排查看主机、时间差以及 DNS/TCP/TLS/HTTP/代理状态。最好选择同一主机且时间接近的记录。两种探测路径可能不同，对照只能提供排查线索。

HAR 原文件可能含 Cookie、授权信息、表单内容及 URL Token。NetEvidence 不保存原文件或分析结果，也不会把请求头、请求体和响应体送到界面；仍请勿直接把原 HAR 发给别人。HTTP 状态 0 表示记录中没有 HTTP 响应，可能由取消、拦截或记录不完整造成，不能直接判定为网络中断。

## 排查间歇性故障

先用单次诊断确认输入和路径，再在预计会复现的时段运行连续采样。故障出现后打开已保存的异常样本，查看最先失败的一层；与正常样本对比网络环境。如浏览器显示空白页而工具的 HTTP 层成功，还应使用浏览器开发者工具检查脚本和接口请求，本工具的首页响应不能证明整个网页已经正常运行。

历史保存在 `%LOCALAPPDATA%\NetEvidence\history`，可在侧栏手动删除或按期限清理。该目录包含未经脱敏的原始证据，不应直接共享。
